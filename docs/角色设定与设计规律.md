# 角色设定与设计规律

本文补充 README 表格之外的深度内容：每个对象的完整技术本体说明、设计符号与真实技术特性的对应关系、以及蓝色大肥鱼站上其余角色的收录情况。

---

## 一、这批立绘对应的对象都是什么

本仓库的 22 张立绘对应的并不是「22 个聊天机器人」，而是**22 个不同层级的技术对象**。搞清楚层级很重要，否则容易把一家公司、它的一个模型、它的一个开源权重、它的一个周边工具混为一谈。

| 层级 | 本仓库中的对象 | 本体是什么 | 关键判别问题 |
| --- | --- | --- | --- |
| **基础模型厂商 + 旗舰模型** | DeepSeek、Qwen（通义千问）、GLM（智谱）、Kimi（月之暗面）、MiniMax、Mistral | 训练并托管模型权重，通过 API 或开源权重对外提供推理能力 | 「这家公司的旗舰模型参数多少、上下文多长、什么协议授权」 |
| **闭源前沿模型** | GPT（OpenAI）、Claude（Anthropic）、Gemini（Google）、Grok（xAI） | 权重不公开，只提供托管 API | 「这个模型在什么基准上强、上下文多大、能不能自部署」 |
| **非 Transformer 架构项目** | RWKV | 一种替代注意力机制的线性注意力架构本身，以开源非营利组织形态存在 | 「它的推理复杂度和显存占用随上下文怎么变化」 |
| **代码托管平台** | GitHub、GitLab、Gitee | 开发者协作基础设施，AI 能力是平台的一层 | 「它是托管代码的平台，还是提供模型推理的」 |
| **模型托管与分发平台** | Hugging Face | 模型/数据集托管 + 工具链 + 协议标准（MCP） | 「它不训练模型，它分发和连接模型」 |
| **AI 编码工具 / 工具外壳** | OpenCode、ZCode（智谱） | 与具体模型解耦的 agent 外壳或开发工作台 | 「它自己有没有模型，还是只负责编排别人的模型」 |
| **AI 创作平台** | NovelAI | 订阅制的写作 + 二次元绘画 SaaS | 「它提供的是创作产品，不是通用 API」 |
| **检索增强问答引擎** | Perplexity | 以自建实时索引 + RAG 管线为核心，而非参数化知识模型 | 「它的知识来自训练权重还是来自实时检索」 |
| **多模态产品线** | 豆包 Seed（字节跳动）、混元（腾讯） | 围绕单一厂商生态的多模态模型矩阵 | 「它是一个模型，还是一整条模型矩阵」 |

> 理解这个分层后，一个直接结论是：**这批立绘的「可对比性」是跨层级的，不是同层级的**。DeepSeek 和 GPT 可以比模型能力，但 DeepSeek 和 GitHub 不在同一维度 —— 它们被放在一起是因为社区都用拟人形象去指代它们，而不在于它们的技术可比。

## 三、设计符号与真实技术特性的对应关系

同一批画师在设计这 22 个形象时，并不是随意配色，而是**把技术特性转译成可识别的视觉母题**。这是这套形象能被社区当成"通用形象"使用的技术前提 —— 看图就能猜出这个模型强在哪。

| 视觉母题 | 承载的技术含义 | 出现在 |
| --- | --- | --- |
| **无限符号 ∞** | 开源权重 / 开放模型身份标识 | Llama |
| **角、尾、异色瞳等二次元化特征** | 承载品牌色的同时提供亲和力锚点 | 全系列通用手法 |
| **书本 / 折扇 / 罗盘提灯** | 模型的核心能力品类（长文本、东方语料、检索探索） | Claude、Qwen、Perplexity |
| **录音设备 / 麦克风 / 声波** | 语音与音频模态能力 | MiniMax、混元 |
| **祥云纹 / 太极纹 / 中式长裙** | 国研模型的中文语料与本土化定位 | Qwen、Gitee、混元 |
| **折纸狐面 / 章鱼触手 / 像素方块** | 直接复用代码托管平台已有的品牌吉祥物 | GitLab、GitHub |
| **无限上下文意象（金属光环、乌鸦、循环纹）** | 长上下文与循环/递推架构 | RWKV |
| **线框与几何角饰** | 代码世界的抽象几何感 | OpenCode |
| **A0 蓝图、工具挂饰** | 编程工作台 / 开发环境 | ZCode |
| **纸卷、羽毛笔、月桂冠** | 绘画与创作工具 | NovelAI |
| **笑脸 / 星星眼** | 开源社区的拥抱姿态 | Hugging Face |

> 可以看到：视觉母题的选择几乎都对应着一项**可验证的技术属性**（协议、上下文长度、模态、语种、架构特征）。这正是这套形象与「随手画的萌系人物」的根本差别。

### 3.1 为什么这套设计能成体系

这批立绘发布于 2026-10-17 前后，同一批次一次性放出多角色（作品 ID 为 `202610170001` ~ `202610170003` 等连续编号），且全部遵循"白底 + 全身 + 立绘"的统一规格。这带来三个直接效果：

1. **可对比性** — 用户可以把不同厂商的形象并排放，判断"哪家的更萌""哪家的更专业"。
2. **可复用性** — 统一规格意味着任何一张都能直接替换进同一个表情包模板、同一套 PPT、同一张角色墙。
3. **可信度** — 同一画师、同一画风、同一规格，比"各画师各画一个"更容易被社区认定为"公认形象"。
