# 美术素材索引

这个仓库最初只想收 30 张立绘。收着收着发现，真正稀缺的不是图，是**知道图在哪、能不能用**。

所以这一页是仓库的核心：一张素材地图。它回答三个问题——**谁在画、画在哪、能不能用**。

## 四、按获取方式

想拿到图，有四种路子，难度和合规性都不同：

| 方式 | 怎么做 | 难度 | 合规性 |
| --- | --- | --- | --- |
| **直取原图** | pixiv 的 `/ajax/illust/<id>/pages` 接口返回每页 `urls.original`；带 `Referer: https://www.pixiv.net/` 即可下载 | 低 | 取决于作者授权 |
| **读站点数据** | 蓝色大肥鱼站是 Payload CMS，源码仓 `data/works.json` 有全部 1112 件元数据 | 低 | 同上，但能一次拿到 author/license |
| **查百科反推** | 萌娘百科的角色条目会列代表画师与 pixiv ID，是最快的找源头方式 | 低 | 仅线索 |
| **问作者** | 通过 pixiv 私信、B 站评论、GitHub issue 直接问授权 | 高 | 最稳 |

## 五、判定标准：为什么大部分没进仓库

找得到 ≠ 能用。这里记的是实际卡住的地方：

| 障碍 | 涉及量 | 具体表现 | 处理 |
| --- | --- | --- | --- |
| **作者未标注** | 1040 件（站点） | 作品页写「图片版权归原作者所有；原作者未标注」 | 只登记索引，不落图 |
| **仓库 MIT ≠ 图片 MIT** | 约 490 张（GitHub） | TreapGoGo 明写「角色设定图、社区投稿及外部项目素材不包含在代码许可中」 | 不收，除非有逐文件许可 |
| **许可字段为空** | 147 件（TreapGoGo） | manifest 有 license 字段但 147 条为空 | 不收 |
| **NOASSERTION** | 87 张（dsh-deep-whale） | 有 LICENSE 文件但 GitHub 无法识别为任何标准协议 | 不收 |
| **平台不可批量取** | pixiv 站内搜索、X、微博 | 需登录或有反爬 | 改为按画师逐个查 |

**一条经验**：仓库标了 MIT 不等于图片是 MIT。代码许可与素材许可是两件事。dsh-whale-galgame 之所以能收，正因为它把两者分开写清楚，还给了 22 行逐文件表。

## 六、这个生态的分工

技术拟人不是零散的同人图，已经形成了有分工的链条。理解这个结构，就知道该去哪个环节找素材：

| 环节 | 代表 | 产出 |
| --- | --- | --- |
| **角色原型** | 上善无形「溟月」 | 单一 OC，CC BY-NC-SA 4.0 开放二创 |
| **二次设计** | ZipZipPipe 女仆鲸鱼娘 | 主表 31 张 + 画廊 16 张，确立了主流形象 |
| **资源库 / 索引** | TreapGoGo/deepseek-whale-girl（618★） | 150 件作品清单、41 位作者 |
| **素材扩展包** | AATINF/deepseek-whale-girl-assets | 202 张细节素材 |
| **皮肤 / 桌宠** | dsh-deep-whale（2917★）、whale-girl（388★） | 十余个插件，各自带图 |
| **应用层** | dsh-whale-galgame、表情包仓、161 个 GIF | 把图组装成产品 |
| **百科** | 萌娘百科 DeepSeek娘 条目 | 记录形象演变与画师 |

**但极度集中在一个对象上。** 上面这些仓库合计 558 张图，几乎全是 DeepSeek 鲸鱼娘。其他模型娘的图仍散在各画师个人主页里，没有形成同等规模的社区。

这也是主表坚持「一对象一张」的原因：按图的数量排，DeepSeek 会吃掉整个仓库。

## 七、采集方法与数据

这一页的数据不是手抄的，是脚本采的。结构化结果存在 [`data/pixiv_artists.json`](../data/pixiv_artists.json)：4 位画师、151 件 AI 相关作品的 id / 标题 / 页数 / 尺寸 / 标签，**只有元数据，不含图片**。可以直接筛，也可以拿去复核。

采集用的接口：

```text
# 1. 画师主页的全部作品 id（只拿 id，很快）
GET https://www.pixiv.net/ajax/user/<uid>/profile/all?lang=zh

# 2. 单个作品详情（标题/页数/标签/尺寸/作者）
GET https://www.pixiv.net/ajax/illust/<id>?lang=zh
Referer: https://www.pixiv.net/artworks/<id>

# 3. 多页作品的原图列表
GET https://www.pixiv.net/ajax/illust/<id>/pages?lang=zh
#     → body[].urls.original，下载时同样要带 Referer

# 4. 站点全量元数据
https://raw.githubusercontent.com/lmy414/bluedafeiyu/main/data/works.json
```

三个坑：

1. **批量接口不可用** —— `/ajax/illust?illust_id=1&illust_id=2` 会 412，只能逐个查，间隔 1.5 秒
2. **缩略图路径全部 403** —— `c/1200x2400/img-master/...` 一律拒绝，只能下原图（单张约 13 秒）
3. **Danbooru 被 Cloudflare 拦** —— 想用它的 tag 体系查角色特征，需要用浏览器
